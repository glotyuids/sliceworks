# Eight findings that carry the design

Collected in October 2026 from vendor engineering posts, the hosting platform's documentation and the published research on multi-agent coding; the first run then tested each against its own telemetry.

1. **Writes stay single-threaded; reads parallelize.** The strongest cross-vendor consensus. The pattern that works is one writer augmented by other agents for review, search and advice. Coding has fewer truly parallelizable pieces than research; sequential, same-file or dependency-heavy work is better done by one session. More agents help only when dependencies are sparse. Hence principles 1 and 2, the writer cap, and read-only helpers.
2. **Parallelism works across isolated, independent units with a merge step and executable tests.** A central planner, asynchronous execution in isolated worktrees and test-verified merges measured double-digit gains on two benchmarks. Hence slices, worktree isolation, contracts frozen before dispatch, merge by SHA with T2.
3. **Long-running work needs a harness, not prose policy.** A feature list with pass flags, an init script, a progress file and a per-session routine fix the three recurring failures: overreach, premature "done", and marking features done without testing. Every harness component encodes an assumption about what the model cannot do alone; remove components as models improve. Hence the ledger, the init command, `PROGRESS.md`, the implementer routine, and the component table.
4. **Verification order: deterministic checks first, then a clean-context reviewer, then a human at the pull request.** Teams that ran the full build and tests before opening a pull request merged nineteen of twenty agent pull requests on the first run. Model output should not become a release gate by itself. A reviewer prompted to find gaps will find some, so restrict it to correctness and let the implementer filter findings against intent. Hence the tiers, the fresh-context reviewer, the severity rule and the implementer's scope decision.
5. **Context is the binding resource.** Recall degrades as the window fills; every turn resends the whole context; scheduled polls and cross-session messages each start a full-context turn; agent teams cost several times a single session. Hence a short always-on file, subagents for anything verbose, no polling by a model, status and dashboard by scripts, six message shapes.
6. **Tokens explain most of the variance, in both directions.** Budget explained most of the quality variance in one study, while another found accuracy peaks at intermediate spend and the same task can vary thirty-fold in cost between runs. Spend where the task is hard, cap where it is routine. Hence model routing by role, budget boxes, and the two-round stop.
7. **Specs help where ambiguity is high, and the evidence for more is thin.** Spec-driven workflows expose unclear requirements early; the only controlled result found is a small quality gain from grounding spec stages in repository evidence. Keep specs short, maintained and attached to a verifiable end state. Hence contracts with golden fixtures and briefs capped at 150 lines, and no task-generation phase.
8. **The hosting platform now provides most of what a team would hand-build.** Subagents with worktree isolation, completion notifications, background sessions, deterministic Stop hooks, scheduled jobs. Custom registries, grant updaters, snapshot tools and a heartbeat manager duplicate these at higher cost. Hence hooks and files instead of a coordination service, and the withdrawn list below.

## What the first run measured and withdrew

The process this method replaced had a five-minute heartbeat that consumed about a seventh of the budget, 42 defaults applied silently, 136 decision rows left unanswered, sealed waves and eligible sets, hash re-verification at intake, receipts, grants and leases. None of it moved a scenario to green. The method keeps what did: one canonical backlog with stable ids, one writer per worktree, merge by SHA, a numbering ledger, independent review on a frozen SHA plus a named-risk second review at material boundaries (both found real High defects), `NOT_RUN` semantics, no-secrets rules, and the scripts that remove model work.
